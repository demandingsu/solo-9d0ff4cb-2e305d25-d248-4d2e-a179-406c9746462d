# 隔声试验数据交付复核工具

声学实验室向外部复核方交付隔声试验数据的网页工具：从上传的 SQLite 库中勾选试验、
剔除个别异常读数，沿对照/校准引用自动补齐所需记录，确认预览后下载 SQLite 子库。

## 运行

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements-dev.txt
python3 scripts/make_sample_db.py sample.db   # 生成演示库
uvicorn app.main:app --reload
```

运行测试：`pytest`

## 数据库结构约定

上传的 SQLite 库需包含四张表（关键列名固定，其余列任意）：

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `groups` | `id`, `name` | 试验组 |
| `calibrations` | `id`, `device` | 校准记录 |
| `tests` | `id`, `group_id→groups`, `calibration_id→calibrations`(可空), `name` | 试验 |
| `readings` | `id`, `test_id→tests`, `calibration_id→calibrations`(可空), `control_reading_id→readings`(可空), `kind` | 读数；`control_reading_id` 为对照读数引用，允许跨组 |

## 交付规则

1. 交付所选试验中未被剔除的全部读数；
2. 沿对照引用（`control_reading_id`）与校准引用（`calibration_id`，读数级与试验级）
   补齐所需记录；对照读数允许跨组互引；
3. 跨到未勾选的组时，只带入沿引用找到的读数，以及这些读数所属的试验、
   试验所属的组（维持外键完整所必需）和引用到的校准记录；
4. 引用悬空（目标不存在）或指向已剔除读数时，预览页展示完整引用链并**阻止下载**；
5. 子库建表语句复用源库 DDL 原文，主键、外键约束、索引原样保留，行按原主键写入，
   导出后执行 `PRAGMA foreign_key_check` 校验。

## 使用流程

1. **上传**：选择实验室导出的 SQLite 库（结构不符会给出具体缺失项）；
2. **选择**：按组勾选要交付的试验，可在所选试验下勾选要剔除的异常读数；
3. **预览**：查看交付汇总、跨组带入的读数及其引用链；若存在引用冲突，
   展示每条冲突的完整引用链，下载按钮禁用；
4. **下载**：确认后下载 `*_subset.db`。下载前服务端会重新解析一次，
   若状态已变化产生冲突则返回 409 拒绝。

## 频点测齐核查

一次扫频的读数入库后，后续提交可能补测、覆盖或撤回读数。核查入口
（上传页的「打开频点测齐核查」，或直接访问 `/check`）用于回答：
**某试验的必测频点最早在哪一笔提交时测齐。**

1. 上传**采集开始时**的 SQLite 主库，以及**同一轮、尚未回填（checkpoint）**的
   WAL 文件（`*-wal`）；
2. 填写试验编号、必测频点（Hz，逗号或空格分隔）；试验若在 WAL 的某笔提交中
   才创建，也可直接填编号；
3. 主库为第 0 版，WAL 中每一笔完整且校验通过的提交算一版（第 1…N 版）；
4. 某频点存在该试验下 `level_db` 非空的读数即算已测，报告首次测齐的
   版本序号及各必测频点当时的读数编号；一直没测齐时，列出最后一版缺少的频点。

判定口径：

- 忽略未提交的数据（末尾未形成提交的帧）和截断的日志尾部（含被截断的帧、
  盐值/校验和不符的后续内容）；这些不会计为版本，页面上会提示忽略了多少字节；
- 主库只复制到工作文件一次，之后按提交顺序把每笔提交的页**原地**写入工作库，
  每版用新的只读连接查询该试验的读数——不会为每笔提交重新复制主库，
  也不回放此前的提交；
- 同一试验下同一个频点出现多条读数时，取编号最大的**非空**读数（NULL/空白
  视为未测；撤回读数即把该笔的 `level_db` 置空）；
- 主库/ WAL 无法读取、主库缺少分析所需列（`tests.id/name`、
  `readings.id/test_id/frequency_hz/level_db`）、WAL 与主库页大小不一致或
  WAL 引用的页号超过其记录的库大小时，页面给出原因；原有单文件上传流程不受影响。

演示样例（先测齐、再撤回读数、再重测，末尾附一笔未提交事务及一份截断的 WAL）：

```bash
python3 scripts/make_wal_sample.py sample_wal
# 生成 sample_wal/in_situ-main.sqlite 与 in_situ-main.sqlite-wal
# 上传这两个文件，选试验 #1，填 100,125,160,200 → 应报告「第 3 版测齐」；
# 换用 in_situ-truncated.sqlite-wal → 只看到第 1 版，提示忽略截断尾部。
```

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATA_DIR` | `./data`（容器内 `/data`） | 上传文件与子库的工作目录 |
| `MAX_UPLOAD_MB` | `200` | 上传大小上限 |

## 已知限制

- 会话保存在单进程内存中，重启后需重新上传；上传文件保留在 `DATA_DIR`，
  需运维定期清理（未实现自动清理）；频点核查的主库与 WAL 副本同样保留在
  `DATA_DIR/<会话>-check/`，每次核查的临时工作库在用完后立即删除；
- 未做多用户隔离与鉴权，仅供实验室内网使用；
- 表名/关键列名固定，如实验室库结构不同需先适配（见 `app/core.py` 顶部约定）。
